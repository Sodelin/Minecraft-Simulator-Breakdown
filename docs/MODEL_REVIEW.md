# Independent model review

Evidence is the purchased `Native/src/mcmacro.c` and `Prototypers/Docs/PROJECT_README.md`. Line numbers refer to the untouched native source. Static inspection establishes implementation behavior; it does not establish equivalence to Minecraft 1.21.4. No engine oracle was executed in this review.

## What the author is solving

The project README lines 3–18 explicitly describes a fast event-driven thought experiment in an abstract Minecraft-like world conditioned on a rare self-beatable seed. Its primary achievement is a complete proposed causal chain and a fast generator of histories under that model. It is not written as a proof of an unmodified zero-player Minecraft execution. The calibration output at 10733–10740 explicitly defines the model year and says despawn, player loading, and vanilla spawn caps are intentionally ignored. Respect those declared choices while checking whether the output accurately represents them.

## Triage: small, demonstrable implementation defects

1. **Geometric sampler is an approximation outside its rare-event regime.** `sample_geometric_rare` (2425–2439) returns `ceil(-log(U)/p)` rather than `ceil(log(U)/log1p(-p))`. The approximation's expected count is `1/(1-exp(-p))`; an exact geometric count has mean `1/p`. A caller uses p=0.24 (9801), and RNG-help can produce p=1 (7896–7909,5470,5500). At p=1 the exact result must always be 1, but the current function can report failed attempts. This affects compressed count claims. Our implementation preserves exactly one uniform draw, including at p=1, and the tests verify subsequent RNG state is preserved. Counters change; logging-only trajectory comparisons apply to the pre-distribution-fix build.
2. **Batch ranking rewards elapsed time.** `parse_batch_progress` (11122–11170) constructs a lexicographic-like scalar score with positive `+ p.simulated_years`; `batch_progress_better` chooses the larger score. Completed histories with identical progress therefore prefer longer elapsed times. This is confirmed ranking behavior, but calling it an objective bug requires deciding whether “best” means fastest success, greatest progress, or longest explored history. It also treats exit code 0 as evidence of dragon death, which is unsafe for non-chain successful commands.
3. **Time-unit disclosure needs to travel with every output.** `model_ticks_per_year` (4823) is 24,000×365 = 8,760,000 ticks. At nominal 20 ticks/s this is 438,000 seconds, or approximately 5.069 civil days. A billion model years is not a billion civil years. This is a labeling/provenance requirement, not a mathematical error in the conversion currently used by the source.

## Triage: structural statistical issues needing a model change

4. **Iteration-clock dependence.** The full-chain loop calls `macro_tick_regional_snow_golems` and `stronghold_maybe_creeper_or_tnt_blast` once per iteration (9203–9208). Their activity, encounter, movement, and death decisions use fixed Bernoulli probabilities (5623–5700;5732 onward), with no elapsed-time argument for regional golems and no conversion of encounter probability by dt. The loop then selects pumpkin versus TNT work by 0.58/0.30/0.46 (9219–9224), after which that selected path advances the clock by its own waiting times. Changing pickup workload or resource availability therefore changes hostile opportunities per simulated year. End-side background advancement similarly uses a fixed event budget `1+N/32`, capped at 64 (5705–5719), rather than a rate integrated across elapsed time. This is not an exact global competing-hazard simulation. A defensible repair requires event rates and a common clock, not another arbitrary probability.
5. **Pickup count and time are not a joint sample from one history.** The competition functions draw a geometric attempt count and independently draw an exponential elapsed time (5470–5477,5500–5507). Poisson thinning makes the exponential successful-pickup time marginal correct for the assumed ordinary Poisson process; it does not make the failure count independent of that time. For ordinary rate λ and success chance p, conditional on successful time T, failures have Poisson mean λ(1−p)T. Alternatively sample the geometric attempt count then sum/gamma-sample its ordinary interarrival times. Independent counters can be acceptable expected-activity annotations if clearly labeled, but they do not form a replay of the same microscopic history.
6. **Biased assistance is a different model, not an unbiased rare-event estimator.** RNG-help changes probabilities (7896–7909), directional selection (7714–7757), placement/death rates (7870–7939), and some stage waits/requirements (9542,9571). No likelihood-ratio weights accompany the output. Assisted paths demonstrate model mechanics and aid debugging. They cannot estimate baseline success probability or expected completion time. At 100% help, even a zero base chance can become certain, which can change reachability rather than merely accelerate a legal path.

## Triage: assumptions that need target-version empirical validation

7. **Spatial aggregation and first-passage behavior.** Local boundary crossing is an exponential hazard derived from stroll rate times `(8/sqrt(area))²`, navigation factor 0.18, and biome factors (7777–7828). This can have diffusion-like scaling, but mean scaling does not validate the full first-passage distribution, especially initial positions near cell boundaries, repeated re-entry, terrain barriers, and far-node return. The coarse node process loses position and waiting-age information. Validate against engine trajectories or a controlled microscopic random-walk oracle, then choose a Markov, semi-Markov, or position-augmented model.
8. **Far-world resources are generated hypotheses.** Far resource area is πr² minus explicit area (4761–4795), with default r=60,000,000 blocks (3605). Far counts divide area by 140,000,000,000 for outposts and 450,000,000,000 for mansions, multiply seed-dependent jitter, and force at least one of each whenever positive far area exists (5090–5111). These densities and deterministic jitter are not actual per-seed structure enumeration. The circular effective radius must be distinguished from a version-specific vanilla rectangular world border. Do not silently substitute a different radius without declaring which world geometry is intended.
9. **Structure presence does not by itself certify usable blocks or routes.** Loaded manifests use their stored resource counts (5035–5044,5065–5075). Generated sources assign 2 TNT per mansion and 3 carved pumpkins per outpost (5056–5059,5084–5087); far resources do likewise (5110–5111). A verified structure start is separate from verification that its optional relevant pieces, accessible target blocks, snow-block arrangement, portal-room access, and trajectories exist. The exporter and verifier must be audited separately before assigning engine-truth status to these claims.
10. **Many consequential End probabilities and waits are stipulated.** The direct-creeper function samples an 8.5-million-model-year wait and independent chances 0.84 provoked,0.075 close,0.55 detonates,0.035 vulnerable,0.20 aligned; damage is uniform integer2–9 (7592–7638). TNT ignition has its own encounter waits, flame-bow chances, geometry proxies, and discrete damage formula (7480–7589). Schematics illustrating accepted configurations are witnesses to the local model, not empirical calibration of these hazards or vanilla blast damage. Target-version controlled experiments should estimate joint encounter distributions and damage, including failures.
11. **Stage serialization is a hypothesis.** The full chain opens three stronghold segments, then enters the End, opens egress, destroys crystals, and only then damages the dragon. All-crystals-first and one useful tower route at a time simplify causal scheduling. They may be conservative or overoptimistic depending on resources and concurrency; neither direction follows automatically. Check persistence, interleaving, regrowth/healing, and destructive collateral effects in an explicit state model.

## Distinct optima and how to compare them

| Objective | Quantity | Fair comparison |
|---|---|---|
| Legal reachability | Does any positive-probability target-version path exist? | Verify every edge, initialization condition, and resource invariant; one witnessed path suffices for the stated setup, not for all seeds. |
| Typical waiting time | Median/quantiles and survival curve of completion time conditional on specified seeds/setup | Keep all independent histories, including timeouts and failures; do not retain only winners. |
| Fastest suitable world | Minimum chosen time functional over allowed seeds | Declare seed-search budget and conditioning; distinguish minimum sampled realization from minimum expected time or a quantile. |
| Rare-event probability | Probability of legal completion by a time horizon | Unbiased direct simulation or validated importance sampling/splitting with weights and uncertainty. |
| Computational efficiency | Error or uncertainty per wall-clock budget | Compare against an oracle and fixed accuracy target; events/s alone rewards uncontrolled approximations. |
| Robustness | Stability across plausible rate/geometry uncertainty | Sensitivity sweeps, adversarial assumptions, convergence across spatial resolutions. |
| Mechanism simplicity | Fewest special conditions, transfers, or fragile transitions | Pareto compare legality, rarity, and time; the shortest causal explanation need not be the fastest stochastic route. |

For a better solver, first expose the objective and model contract. Preserve separate world seed, event RNG seed, target version, loading/spawning modifications, resource inventory, assistance mode, horizon, and all censoring reasons. Then build a shared-clock scheduler for calibrated transitions. Constant independent exponential hazards permit a Gillespie event race; non-exponential first-passage times need a semi-Markov/event-queue treatment. Rare-event acceleration can use importance sampling only when likelihoods are known and carried through the result, or splitting with complete lineage accounting. Exact number theory can improve candidate-seed search and certify procedural constraints; it cannot supply missing physical encounter rates.

## Preliminary next architecture: a validation ladder, not a rate replacement

1. **Contract and state.** Specify the target setup (literal vanilla or deliberately modified), actual initial entities, dimension/chunk activity, world border geometry, seed conditioning, and available blocks. Store a typed state and conservation ledger. Declare model time in ticks; render Minecraft days/model years as derived units.
2. **Microscopic oracles.** Use target-version reproducible fixtures for block acquisition and placement, pumpkin-on-two-snow-block construction, explosion excavation, hostile retaliation, portal traversal/initialization, crystal arrows, and dragon damage. Record successes and failures plus initial conditions. An illustrative exported scene is distinct from executing the chain.
3. **Validated reduction.** Fit encounter hazards/first-passage kernels with confidence intervals and retained spatial state. Compare reduced model survival curves and joint outcomes to held-out fixtures. Vary macro resolution and cell-entry position. Where memorylessness fails, use scheduled first-passage distributions or supplementary age/position state.
4. **One physical clock.** For constant competing hazards a_i(s), use A=sum_i a_i(s), sample Δt=−log(U)/A, choose event i with probability a_i/A, then update state and affected hazards. Include resource pickups, transfers, golem movement/death, hostile encounters, and damaging interactions in the same race. If a hazard varies deterministically between events, invert its integrated cumulative hazard or use validated thinning. Fixed Bernoulli decisions per outer software iteration have no role as physical rates.
5. **Rare-event acceleration with an estimator.** Under proposal hazards b_i(s)>0 wherever a_i(s)>0, a continuous-time path's log weight is sum_events log(a_i/b_i) minus integral(A−B)dt, with matching initial-state/seed-selection weights when applicable. Report effective sample size, weight concentration, estimator uncertainty, and sensitivity. A proposal may never create a target-impossible transition. Splitting is an alternative, with complete genealogy, resampling weights, and controls for dependent offspring. These are preliminary methods; no claim of optimality before benchmarks.
6. **Ensembles and censoring.** Keep every run's world/event seeds, config/source/manifest hashes, physical horizon, terminal condition, and wall timeout. Deterministic physical-horizon truncation supports a survival estimate; a computational wall timeout may induce state-dependent censoring, so merely applying Kaplan–Meier does not solve it. Prefer a common physical horizon; otherwise model censoring or report explicit bounds and incomplete-run fractions. Separate irreversible extinction from administrative censoring.
7. **Optimization layers.** Seed search optimizes a distribution of worlds and has its own computational budget. Conditional-world simulation estimates histories within a chosen world. An assisted best path is a debugging/feasibility search result. Minimum observed time, expected time, probability by horizon, and legal reachability are different targets. Use a Pareto frontier when trading rarity, time, compute, and fragility rather than an unexplained scalar “best”.
